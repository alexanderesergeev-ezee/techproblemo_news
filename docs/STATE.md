# Фактическое состояние

Дата обновления: 14.09.2026.

## Реализовано в TASK-001

- Python-пакет с командой `run-once --offline` для синтетического JSONL.
- Версионированная начальная схема SQLite: источники, материалы, анализы, доставки и runtime state.
- Точные повторы по `(source_id, source_item_id)` не создают повторный анализ или доставку.
- Mock-классификатор воспроизводит ответ фикстуры; JSON Schema и наличие evidence в исходном
  тексте проверяются локально. После трёх предусмотренных попыток невалидный ответ получает FAILED.
- При `relevance_score > 0.70`, достаточном контексте и целевой категории анализ и PENDING-доставка
  создаются одной транзакцией. Файловый sender переводит её в SENT после записи строки JSONL.
- Пустой текст получает SKIPPED_NO_TEXT, недостаточный контекст — NEEDS_REVIEW.
- Добавлены pytest, Ruff, GitHub Actions и воспроизводимый setup для Python 3.12.

## Проверено локально

Результаты фактически выполненных команд и демонстрационного запуска записаны в
`docs/DEMO_OFFLINE.md`. Тесты используют только синтетические данные, без сети и секретов.

## Не проверено и не реализовано

Реальные источники и права на них; внешний LLM; Telegram Bot API; качество классификации;
стоимость и задержки внешних вызовов; сервер Ellery; контейнеризация, эксплуатация, backup/restore.
Файловая доставка подтверждает только offline-механику и не является обещанием exactly-once.

## Согласованность исходных документов

Существенных продуктовых противоречий между SPEC и TASK-001 не найдено. Обнаружено нарушение
структуры стартового пакета: документы и фикстуры находились в корне под именами соседних файлов,
хотя README и manifest задавали каталоги `docs/`, `tasks/`, `schemas/`, `config/`, `evals/`.
Структура восстановлена без изменения границ продукта. Указание SPEC о Telegram-доставке описывает
целевую версию 0.1, а файловый sender прямо задан как ограничение offline TASK-001.
