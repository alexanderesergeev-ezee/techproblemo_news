## TASK-001 — offline-версия
Прочитай AGENTS.md, SPEC.md, docs/STATE.md и сценарии. Сначала найди существенные противоречия; исправь документацию только в пределах указанной задачи и обозначь изменения.

Реализуй минимальный Python-пакет: чтение синтетических материалов, локальная SQLite с миграцией, точные повторы, заглушка классификатора с заданными JSON, проверка схемы и условий отбора, очередь доставок, файловый sender. Добавь `python -m techproblemo_news run-once --offline`. Повторный запуск с теми же данными не должен создавать новые обычные доставки. Реализуй строгую границу >0.70, а не >=.

Добавь pytest, Ruff и GitHub Actions с чтением репозитория без production-секретов. Выбирай зависимости минимально, фиксируй воспроизводимые версии. Сеть в обычных тестах запрещена. Не добавляй реальный Telegram reader, API-ключи, Docker-деплой, веб-интерфейс или другие сервисы.

В README укажи реальные команды установки и запуска. В STATE укажи только подтверждённое. Создай небольшой PR с соответствием требований тестам, результатами команд и известными ограничениями. Не сливай PR.

## TASK-002 — один разрешённый источник и один LLM API
Предусловия: TASK-001 принят; владелец выбрал источник, подтвердил допустимость обработки и модель/провайдера. Без этих сведений реализуй интерфейс адаптера и его mock-тесты, но не активируй сбор.

Добавь один input-адаптер с курсорами/пагинацией и один LLM-адаптер. Соблюдай лимиты, тайм-ауты, retry, локальную проверку JSON и опорных цитат. Накапливай usage и сохраняй версию промпта/модели. Для OpenRouter проверь совместимость конкретного endpoint с нужными параметрами; не делай динамический непроверенный fallback. Для GigaChat используй его реальный официальный API/авторизацию, а не предполагаемую полную OpenAI-совместимость. Не отключай TLS.

Live-проверка выполняется отдельно владельцем с ключами вне репозитория. Пока доставка остаётся файловой. Отчёт отделяет mock-проверки от настоящих API-вызовов.

## TASK-003 — Telegram-доставка
Предусловия: тестовый бот создан владельцем, пользователь начал диалог, получатель явно разрешён. Реальные значения не включать в код и отчёт.

Добавь Telegram sender через Bot API: короткая карточка, allowlist, SENT с message_id, retry_after при 429 и UNKNOWN при неопределённом исходе. Реализуй операторские команды для просмотра/разрешения UNKNOWN с явным подтверждением. Не создавай слепой retry для SENDING после рестарта. Покрой S12–S15, S23 и падение между внешней отправкой и записью результата. Не заявляй exactly-once.

Реальная отправка — отдельный smoke test владельца; тесты Codex без production-доступа. Публичный канал и редакторские кнопки не добавлять.

## TASK-004 — регулярная работа и размещение
Предусловия: сервер проверен, доступные ресурсы и отдельные пути согласованы; остальные задачи приняты.

Добавь один Dockerfile/Compose project с постоянным локальным volume, ограничениями ресурсов, непривилегированным пользователем, ротацией логов и без входящих портов. Приложение запускается каждые 10 минут одним worker; due-источники собираются с интервалом 60 минут. Защита от второго экземпляра обязательна.

Добавь команды статуса, консистентного backup/restore и осторожного восстановления очереди. Секреты только server-side. В OPERATIONS укажи проверенные команды запуска конкретного проекта, обновления по commit, smoke test, остановки и восстановления. Не изменяй другие контейнеры. Предложи инструкцию ручного деплоя владельцу, не выполняй его из Codex.
